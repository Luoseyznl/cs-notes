# 1. 什么是 Linux？（核心架构与生态）

> 我们通常说的 Linux，其实是 Linux 内核与 GNU 操作系统工具的结合体（GNU/Linux）。一个完整的 Linux 操作系统通常由四部分组成：**Linux 内核 (Kernel)**、**GNU 工具、Shell**、**Linux 桌面环境**以及各种应用程序。

## 1.1 核心架构
### 1.1.1 Linux 内核 (Kernel)

![Arch](images/framework.png)

> 内核是 Linux 系统的核心。它位于计算机硬件与应用程序之间，作为一个“超级管家”全权把控系统的运行。Linus Torvalds 在 1991 年还在赫尔辛基大学读书时，发布了 Linux 内核的第一个版本（0.01）。起初他只是想仿造一款 Unix 系统而已。

内核主要负责以下四个核心功能：

- **系统内存管理**：内核不仅管理服务器上的物理内存（RAM），还负责虚拟内存的分配和管理。
- **软件程序管理**：Linux 将运行中的程序视为进程（Process），内核负责创建、调度和终止这些进程。
- **硬件设备管理**：内核通过设备驱动程序（Driver）与计算机的各种硬件设备进行通信和控制。
- **文件系统管理**：Linux 最强大的特性之一就是能够兼容各种文件系统格式，通过 VFS 接口。

#### 1. 系统内存管理

内核通过在磁盘上划出交换区（Swap Space）来实现虚拟内存：当物理内存不足时，内核会将不常用的数据从 RAM 移动到交换区，以释放 RAM 给当前需要使用的程序。在触发缺页异常（Page Fault）时，内核会将所需的页面从磁盘加载回 RAM。虚拟内存机制允许系统运行比物理内存更大的程序，并提供了内存保护和隔离的功能，防止不同进程之间互相干扰。

内核通过内存管理单元（MMU）实现虚拟内存的分配和管理。它将物理内存划分为页（Page），并通过页表（Page Table）来映射虚拟地址到物理地址。

#### 2. 软件程序管理

> “万物皆文件，余者皆进程。”（Everything is a file, the rest are processes.）

无论是早期还是现代 Linux，普通进程由内核直接调度，用户可以通过 `ps` 或 `top` 查看，通过 `kill` 向内核发送系统信号（Signal）强制结束，内核还支持将进程挂起或在后台运行。

内核启动后，会立即在内存中创建系统上的第一个进程（PID 为 1），由这个“老祖宗”进程来负责拉起和管理所有随开机启动的系统级后台服务（守护进程 Daemon）。这部分是 Linux 发行版演进差异最大的地方：

1. **经典机制 SysVinit**：SysVinit 是 Linux 最早的初始化系统，内核加载名为 init 的 1 号进程，它通过读取 `/etc/inittab`，串行调用 `/etc/init.d/` 目录中的 Shell 脚本来启动或停止服务（早期运维通过 `service` 命令控制）。它使用运行级别 (Runlevel，0-6) 来定义系统状态，如 1 为单用户维护模式，3 为多用户命令行模式，5 为图形界面模式。

2. **现代机制 systemd**：现代主流发行版（如 Ubuntu 16.04+, RHEL 7+）几乎已全面弃用 init，改用 `systemd` 作为 1 号进程。它舍弃了低效的串行脚本，改用统一的单元文件（Unit，存放在 `/etc/systemd/system/`）实现服务并行启动。现代运维统一使用 `systemctl` 命令来控制服务的启停。它用 target 概念取代了运行级别（如 `multi-user.target` 对应原级别 3）。

#### 3. 硬件设备管理

> **“一切皆文件”**

Linux 将硬件设备也视为特殊的*节点*文件（设备文件通常位于 `/dev` 目录下），通信通过读写这些文件来完成。每个节点都有唯一的数值对（主设备号 Major 和次设备号 Minor）来标识设备类型和具体设备。主要分为三类：

**字符型设备 (Character)**：每次只能处理一个字符的设备（如终端、鼠标）。

**块设备 (Block)**：每次处理一个数据块的设备（如硬盘、USB 设备）。

**网络设备 (Network)**：采用数据包发送和接收数据的设备（如网卡、回环设备 loopback）。

#### 4. 文件系统管理

内核必须在编译时就加入对所有可能用到的文件系统的支持。如 ext4、XFS、Btrfs、FAT32、NTFS 等。内核通过虚拟文件系统（VFS）接口来统一管理不同类型的文件系统，使得用户和应用程序可以无缝访问各种存储设备上的数据。

| 文件系统 | 演进机制、优缺点与现状 |
| :--- | :--- |
| **1. Linux 原生文件系统** | |
| ext | 首个专门为 Linux 设计的文件系统。优势：突破了 Minix 系统的限制。劣势：存在严重的磁盘碎片化问题，且最大仅支持 2GB 文件。(已极少使用) |
| ext2 | 引入 inode 表与数据块管理。优势：解决了碎片化问题，极其稳定，长期作为早期 Linux 标配。劣势：无日志功能，系统崩溃或意外断电后，重启时执行 fsck 检查全盘极其缓慢。 |
| ext3 | 引入日志功能 (Journaling)。优势：记录数据更改的轨迹，大幅提升了断电/崩溃后的数据恢复速度。劣势：日志记录会消耗部分磁盘性能，且不支持动态磁盘碎片整理。 |
| ext4 | 引入区段 (Extents) 与延迟分配。优势：极大地提升了处理大文件和海量存储的性能，是现代多数 Linux 的主流标配。劣势：为了安全和性能，删除文件时会彻底清空相关指针，导致误删后数据恢复极其困难甚至不可能。 |
| XFS | 引入分配组 (Allocation Groups)。优势：高性能 64 位企业级日志文件系统，并发读写能力极强，极擅长处理超大文件。劣势：文件系统体积只能扩大不能收缩。(现代 RHEL/CentOS 默认) |
| ReiserFS | 引入B*树结构。优势：早期以小文件处理极快著称。劣势：由于作者入狱等历史原因，后续缺乏商业支持与维护。(已极少使用) |
| **2. 网络文件系统** | |
| proc | 极其重要的虚拟文件系统，存在于内存中，用于动态映射内核状态与进程信息。(Linux 核心机制) |
| nfs | Unix/Linux 服务器之间挂载共享目录的标准网络协议。(Unix/Linux) |
| smb | 用于 Linux 与 Windows 系统之间进行网络文件共享的协议。(Windows/Linux 互通) |
| **3. 跨平台文件系统** | |
| ntfs | 现代 Windows 系统的默认文件系统，支持大文件与权限控制。(Windows) |
| vfat | 即 FAT32 文件系统，单文件不能超过 4GB，但跨平台兼容性极强。(各类系统 / U 盘标配) |
| msdos | 早期的 FAT16 文件系统。(早期 DOS / Windows，已极少使用) |
| iso9660 | 国际标准的 CD/DVD-ROM 光盘只读文件系统。(通用光盘格式) |
| **4. 早期 Unix 文件系统** | |
| minix | Linux 诞生之初 Linus 借鉴的教学级文件系统。(Minix，已极少使用) |
| jfs / hpfs | 分别是 IBM 与 OS/2 的遗留高性能文件系统。(AIX / OS/2，已极少使用) |
| sysv / ufs | 早期 System V Unix 与 BSD 系统的标准文件系统。(老旧 Unix / BSD，已极少使用) |
| umsdos / ncp | 建立在 DOS 上的类 Unix 文件系统 / Novell NetWare 网络文件系统。(遗留系统，已极少使用) |

### 1.1.2 GNU 工具与 Shell

> 当年 Linus Torvalds 开发出 Linux 内核后，面临一个尴尬的局面：有底层系统，但没有可用的上层操作工具。幸运的是，GNU 组织（GNU's Not Unix）早在 1983 年就开始开发一套完整的自由软件操作系统工具（GNU 工具），包括编译器、文本编辑器、文件管理工具等。两者一拍即合：**Linux 内核 + GNU 操作系统工具 = 完整、功能丰富的开源操作系统**。

#### 1. 核心 GNU 工具

供 Linux 使用的基础命令行工具通常由 GNU 组织提供。其中最核心的是 **coreutils (GNU Core Utilities)** 软件包，配合其他几个关键的基础软件包，主要包含三大类工具：

**文件处理工具**：如 `ls`（列出目录内容）、`cp`（复制文件）、`mv`（移动/重命名文件）、`rm`（删除文件）。

**文本处理工具**：如 `cat`（输出内容）、以及强大的三剑客 `grep`（文本搜索）、`awk`（数据提取）、`sed`（流编辑器）。

**进程管理工具**（主要出自 procps 包）：如 `ps`（显示进程状态）、`top`（实时监控资源）、`kill`（终止进程）。


#### 2. Shell (命令解释器)

Shell 的概念在 Unix 时代就有了（Shell 意为“壳”，与内核 Kernel 相对）。用户输入人类可读的文本命令，Shell 负责解释这些命令，并传递给内核去执行。Shell 自带了一些基础的**内部命令**（如切换目录），同时也能接收指令去启动磁盘上的其他外部应用程序。

如果把多个 Shell 命令按逻辑写进一个文本文件里批量执行，这个文件就是 **Shell 脚本**。

| Shell | 全称/溯源 | 核心特点与应用场景 |
| :--- | :--- | :--- |
| **bash** | Bourne again shell | **GNU 项目主力开发**。Unix 标准 Bourne shell 的开源替代品。兼容性极强，是目前**几乎所有 Linux 发行版的默认标配**。 |
| **zsh** | Z shell | 结合了 bash、tcsh 和 korn 的诸多优点。提供高级编程特性、共享历史记录和极度丰富的主题提示符。（现今在开发者群体中极其流行，如 macOS 已采用其为默认终端）。 |
| **ash** | Almquist shell | 极其轻量级的 shell，占用内存极低，但与 bash 完全兼容。通常用于路由器、嵌入式等资源受限的系统。 |
| **korn (ksh)** | KornShell | 兼容早期的 Bourne shell，但引入了关联数组、浮点运算等高级编程特性，在早期的商业 Unix 系统中很常见。 |
| **tcsh** | TENEX C shell | 最大的特点是将 **C 语言** 的语法元素引入到 shell 脚本中，深受有 C 语言背景的工程师喜爱。 |


### 1.1.3 Linux 桌面环境

> Linux 的核心哲学是 **“完成工作的方式不止一种”**，用户可以根据个人喜好和电脑配置，自由选择和切换桌面环境。

图形化桌面在架构上分为**底层显示协议**和**上层桌面环境**两部分：

#### 1. 底层显示协议（X Window System 和 Wayland）

**X Window System（简称 X11）**是 Linux 最早的图形显示协议，直接和 PC 上的显卡及显示器打交道，负责控制窗口和图形的渲染。在 Linux 中有许多软件包实现了 X11 协议，其中最流行的是 X.org。

**Wayland** 是一个更轻量级的显示协议，比 X11 更安全流畅。 它简化了图形堆栈，减少了中间层的复杂性，从而提高性能和安全性。目前，Wayland 已经被许多 Linux 发行版采用为默认的显示协议（如 Fedora、Ubuntu 22.04 及以后版本），但 X11 仍然在一些特定场景（如远程桌面、某些专业图形应用）中被广泛使用。


#### 2. 上层桌面环境（GNOME、KDE Plasma、XFCE 等）

底层协议只负责图形显示，而真正的用户界面则由上层的桌面环境（Desktop Environment）提供。主流的桌面环境包括：

| 主流桌面环境 | 核心特点与适用场景 | 链接 |
| :--- | :--- | :--- |
| **GNOME** | GNU 网络对象模型环境，目前 Linux 世界最流行的标配（Ubuntu 默认）。界面简洁现代，适合新手和追求稳定性的用户。 | [GNOME 官网](https://www.gnome.org/) |
| **KDE Plasma** | 界面华丽，资源占用较高，以高度可定制和丰富的功能著称。适合从 Windows 迁移过来的用户。 | [KDE 官网](https://kde.org/) |

KDE 和 GNOME 虽然华丽，但占用内存较大。Linux 的魅力在于“返璞归真”，对于配置较老旧的电脑，可以选择极低内存开销的轻量级桌面：

| 轻量级桌面环境 | 核心特点与适用场景 | 链接 |
| :--- | :--- | :--- |
| **XFCE** | **轻量级中的王者**。既保留了类似 KDE 的完善功能和传统面板，又极其节省系统资源，速度极快（如 Xubuntu 默认采用）。 | [XFCE 官网](https://xfce.org/) |
| **Fluxbox** | **极简主义**。没有面板，只有一个用来启动程序的右键弹出式菜单，适合极限压榨硬件性能。 | [Fluxbox 官网](http://fluxbox.org/) |
| **JWM** | 超轻型桌面（Joe's Window Manager），适用于极低内存和极小硬盘空间的微型 Linux 发行版（如 Puppy Linux）。 | [JWM 官网](https://joewing.net/projects/jwm/) |


## 1.2 Linux 发行版（Distros）

> 我们将完整的 Linux 系统包称为发行版（Distro）。每个发行版都包含 Linux 内核、GNU 工具、Shell、桌面环境以及各种应用程序。不同的发行版在包管理器、默认软件、系统配置等方面有所差异，适合不同的用户需求和使用场景。

#### 1. **核心 Linux 发行版**包含几乎所有能见到的 Linux 应用，提供大而全的基础环境。它们通常是整个 Linux 生态的“祖师爷”，衍生出了无数子分支。

| 发行版 | 核心特点与历史地位 |
| :--- | :--- |
| **Debian** | 1993 年诞生的老牌发行版，以极度稳定和严谨著称，在专家和商业产品中极受欢迎（庞大的 Ubuntu 家族即衍生于此）。 |
| **Red Hat Enterprise Linux (RHEL)** | 1995 年诞生的商业发行版，主要用于企业级服务器，提供长期支持和稳定性（CentOS 是其免费版本，现已被 Rocky Linux 和 AlmaLinux 取代）。 |
| **Fedora** | 由 Red Hat 赞助的社区发行版，追求最新技术和创新，常作为 RHEL 的测试平台。 |
| **Slackware** | 1993 年诞生的经典发行版，坚持 Unix 传统，配置高度依赖手动编辑文本，是硬核 Linux 极客的浪漫。 |
| **openSUSE** | 由 SUSE 公司赞助的社区发行版，提供稳定的企业级环境和创新的开发工具（如 YaST）。 |

#### 2. **特定用途发行版**基于上述核心发行版构建，但进行了高度定制，旨在做到“开箱即用”。

| 发行版 | 底层 | 核心特点与适用场景 |
| :--- | :--- | :--- |
| **Ubuntu** | Debian | 2004 年诞生，默认使用 GNOME 桌面，提供 LTS 长期支持版本。 |
| **Linux Mint** | Ubuntu | 以用户友好和美观著称，默认使用 Cinnamon 桌面，适合 Windows 用户过渡。 |
| **CentOS** | RHEL | 2004 年诞生，免费版本的 RHEL，提供企业级稳定性（现已被 Rocky Linux 和 AlmaLinux 取代）。 |
| **Kali Linux** | Debian | 专为网络安全和渗透测试设计，预装了大量渗透测试和安全分析工具。 |
| **Puppy Linux** | 现多基于 Ubuntu/Slackware | 极轻量级发行版，适用于老旧硬件和资源受限的系统，提供快速启动和基本功能。 |

#### 3. **免安装测试版**：Live System (LiveUSB / LiveCD)

为了让大家“不破坏现有电脑系统”就能体验 Linux，社区发明了 LiveCD 技术。原理是将一个精简版的 Linux 操作系统烧录在光盘或 U 盘中。通过修改电脑启动项，直接从外置存储设备将系统加载到内存中运行，完全不触碰原本硬盘上的 Windows 系统。

现代 Linux 发行版（如 Ubuntu, Fedora）的安装镜像默认都具备 LiveUSB 功能。可以用 U 盘随身携带一个完整的系统，甚至可以配置持久化存储（Persistent Storage），让你在 U 盘里保存的文件和系统设置在重启后依然保留。
