## 第 11 章 构建基本脚本

### 1. 脚本基础与显示输出

shell 脚本的核心在于将多个命令串联起来自动化执行。但在执行前，系统必须知道“用什么语言来读它”（定位解释器）以及“我有没有资格运行它”（权限）。

`#!/bin/bash` 释伴 (Shebang)：必须严格出现在脚本文件的绝对第一行。它告诉 Linux 内核：“请启动 /bin/bash 这个解释器，由它来逐行读取并执行这篇文档里的代码”。如果是 zsh 就会写 `#!/bin/zsh`。
`command1 ; command2` 多命令并行：在同一行运行多个命令，由分号隔开。shell 会严格按顺序处理，只有等 command1 彻底执行完毕后，才会开始执行 command2。
`echo "Message"` 显示消息：在终端屏幕上打印一段文本。默认情况下，打印完这段文本后，光标会自动跳到下一行（自带回车换行效果）。
`echo -n "Message"` 消除换行：打印文本后不换行。通常用于给出提示语，让随后运行的命令的输出（比如 date 的时间）能够紧挨着这句提示语，显示在同一行里，看起来更紧凑。
`echo $PATH` 查看搜索路径：PATH 是系统的一个“大黄页”。当你敲下一个命令时，shell 只会在 PATH 定义的这几个固定目录里去找对应的可执行文件。找不到就会报错 "command not found"。
`./script_name` 显式引用：出于安全考虑，Linux 默认不会把当前所在目录（.）放进 PATH 里。所以你要运行当前目录下的脚本，必须加上 `./`，明确告诉系统“就在当前目录下找这个文件”。
`chmod u+x test1` 授权执行：新建的文本文件默认只有读（r）和写（w）权限。`u` 代表文件属主(user)，`+x` 代表增加执行(execute)权限。没有这一步，系统会拒绝运行并报错 "Permission denied"。

### 2. 使用变量

变量是你脚本里的“临时储物柜”。环境变量是系统提供的公共储物柜，而用户变量是你自己在脚本里建的私有储物柜。

`set` 显示列表：在终端打印出当前系统所有的环境变量清单，方便你查阅系统预设了哪些信息。
`$USER` (或 `$UID`, `$HOME`) 引用环境：直接提取系统维护的信息。比如 `$HOME` 会自动被替换成当前用户的家目录路径（如 `/home/ubuntu`），这比写死绝对路径要灵活得多。
`\$15` 转义字符：在 shell 中，`$` 看到字母就想把它当变量解析。如果你只是想单纯打印“15美元”，必须在前面加个反斜线 `\`，剥夺 `$` 的特殊含义，将其变为普通文本字符。
`var1=10` 定义用户变量：自己创造一个变量。**极其重要的铁律：变量名、等号、变量值之间绝对不能有哪怕一个空格**。写成 `var1 = 10` 系统会误以为你要运行一个叫 var1 的命令。
`value2=$value1` 引用变量：当你需要使用（读取）储物柜里的东西时，必须拿 `$` 这把钥匙；但当你给储物柜贴标签（赋值，放在等号左边）时，千万不要加 `$`。
`export var1` 导出变量：默认情况下你定义的 `var1` 只能在这个脚本内部存活。使用 `export` 会将它升级为“环境变量”，这样如果你的脚本启动了其他子脚本或子程序，它们也能看到并使用这个变量。

> **作用域总结：** 环境变量是“穿透”的（子进程可继承）；用户变量是“封闭”的（仅在当前脚本、当前进程的生命周期内有效，运行完就灰飞烟灭）。

### 3. 进程关系与命令替换

命令替换能让你把一条命令的运行结果，直接塞进一个变量里，这是脚本自动化的灵魂。

| 术语 | 产生方式 | 关系说明 |
| :--- | :--- | :--- |
| **父 Shell** | 当前终端窗口 | 你敲击键盘的这层环境，是所有操作的根基。 |
| **子进程** | 执行外部命令或脚本 | 独立的程序（如运行 python 或 ls）。它只能看到父 Shell `export` 出来的环境变量，看不到普通的局部变量。 |
| **子 Shell** | 使用 `( )` 或 `$( )` | 父 Shell 动态克隆出的一个“平行宇宙”。它能看到父环境里的所有变量，但它在里面做的任何修改，都会在运行结束后随着平行宇宙一起毁灭，无法带回现实（父 Shell）。 |

`testing=$(date)` 现代命令替换：这是最推荐的写法。它会在后台开启一个子 Shell 运行 `date` 命令，截获屏幕原本要输出的时间字符串，并把它塞进 `testing` 变量里。它支持嵌套，比如 `$($(命令))`，阅读起来也像括号一样直观。
`` testing=`date` `` 传统命令替换：使用键盘左上角的反引号提取输出。这是老派写法，由于反引号很容易和单引号混淆，且极难嵌套，现代工程中应尽量避免使用。

> **经典陷阱：** 因为命令替换是在**子 Shell** 中运行的，如果你写了 `res=$(cd /tmp; ls)`，虽然它确实列出了 `/tmp` 的文件，但这行代码执行完后，你的主脚本依然留在原目录，因为那个执行 `cd` 操作的子 Shell 已经随风消逝了。

### 4. 重定向输入和输出

默认情况下，命令从键盘吸入数据，往屏幕吐出数据。重定向操作符可以强行改变这些数据流的起点和终点。

`command > outputfile` 输出重定向：把命令本该打印在屏幕上的字，强行写进一个文件里。**注意：这是毁灭性的**，如果文件已存在，它会清空原文件再写入新内容。
`command >> outputfile` 追加重定向：同样是写入文件，但它是温柔的。它不会破坏原文件，只会把新的输出像写日记一样，追加到文件的最末尾。
`command < inputfile` 输入重定向：让命令不再等待你敲键盘，而是直接去读取一个文件里的内容作为素材处理（比如用 `wc < test.txt` 统计文件的字数）。
`command << EOF` 内联输入重定向：当你的脚本需要给某个命令自动输入好几行文字时使用。`EOF`（End Of File）只是个约定的界限标记，它告诉系统：“接下来这几行都是要送给命令的内容，直到你再次看到单独占一行的 EOF 为止”。

### 5. 管道

管道（Pipeline）是 Linux 哲学的集大成者，它像流水线一样把多个小工具串起来完成复杂任务。

`command1 | command2` 建立管道：在内存中直接对接。`command1` 每吐出一点数据，不会存到硬盘上，而是立刻顺着管道流进 `command2` 的嘴里作为输入。两者是同时在内存中并排运行的，效率极高。

### 6. 执行数学运算

由于 Bash 的本职工作是处理文本和调用程序，它的数学能力非常弱，原生仅支持整数，碰到小数会直接懵掉。

**整数运算方案**
`expr 1 + 5` 传统计算：极其古老且笨拙。星号 `*` 会被误认作匹配所有文件的通配符，必须写成反斜线转义 `\*` 才能做乘法。
`var=$[1 + 5]` 过渡语法：曾经流行的方括号运算，无需转义符号，但在现代 Bash 中已属于被标记为过时（deprecated）的写法。
`var=$(( 5 * 2 ))` 现代标准：**双圆括号计算扩展**。目前最推荐的写法，不仅安全，还能进行复杂的数学求值并返回结果。
`(( var = a + b ))` 高级数学逻辑：**独立双圆括号**。专门用于执行数学逻辑（如赋值、自增 `(( i++ ))`）。在它内部写代码就像写 C++ 一样，**变量前不需要加 `$` 符号，且随便加空格都不会报错**。

**浮点运算方案**
`echo "scale=4; 3.44 / 5" | bc` 调用 bc 计算器：把带有小数的算式，作为文本通过管道喂给 Linux 内置的 `bc` 科学计算器。`scale=4` 是在告诉计算器：“除法结果请帮我保留 4 位小数”。
`var=$(bc << EOF ... EOF)` 复杂计算块：如果你要算一个极其复杂的物理公式，可以用内联重定向开启一个 `bc` 运算块，里面可以定义临时变量、换行写公式，最后把最终结果通过 `$()` 捕获到 shell 变量 `var` 中。

### 7. 退出脚本与状态码

脚本就像派出去的使者，回来时必须向系统（父 Shell）汇报任务是成功了还是搞砸了。这个汇报信号就是“状态码”（0~255的数字）。

`echo $?` 查看状态码：一个非常特殊的系统变量。它永远记录着**刚刚执行完毕的上一条命令**的最终下场。按照系统惯例，0 代表大功告成，任何非 0 的正数（如 127 找不到命令，126 权限拒绝）都代表出了差错。
`exit 5` 自定义退出：默认情况下，脚本会拿最后一行代码的状态码作为整个脚本的状态码。你可以用 `exit` 命令强行中止脚本，并指定向外播报状态码 5。
`exit $var` 变量退出：使用之前计算出的变量值作为任务结论汇报出去。

> **模运算 (Modulo) 截断现象：**
> 计算机底层用来存储这个退出状态码的空间非常小，只有 8 个比特（8-bit 无符号整数），这意味着它最多只能装下 0 到 255 的数字。如果你强行 `exit 300`，系统装不下，就会对 256 取余数（做模运算：300 ÷ 256 的余数是 44）。所以你在外面用 `echo $?` 看到的实际状态码会变成 44。
