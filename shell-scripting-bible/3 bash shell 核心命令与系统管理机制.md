# Bash Shell 核心命令与系统管理机制

在了解具体的 Bash Shell 命令之前，我们先来看 Linux 处理资源的底层逻辑：**虚拟目录树**与**基于 U-G-O 的多用户权限模型**。

## 1. 虚拟目录树（Virtual Directory Tree）

与 Windows 按驱动器划分文件系统（C 盘、D 盘）不同，Linux 采用虚拟目录（Virtual Directory）结构，将计算机上的所有物理存储设备拼接成一个单一的目录树（Directory Tree）。根目录 `/` 是整个文件系统的起点，所有文件和目录都挂载在这个树上。

![文件系统](<images/3. shell/fhs.png>)

所谓**挂载（Mount）**，就是将一个存储设备（如硬盘分区、U盘）上的文件系统，连接到 Linux 树形目录的某个节点（inode）上。
在挂载之前，挂载点就是根目录 `/` 所在磁盘上的一个普通文件夹；挂载后，这个文件夹就变成了连接外部设备的“入口”，访问它就相当于访问那个设备上的文件系统。

早期 Unix 时代的硬盘太小了，系统不得不一分为二：系统启动、修复和挂载其他硬盘所绝对必需的最少命令和库放在根目录所在的磁盘下（`/boot`、`/bin`、`/sbin`、`/lib`），而其他用户级的软件和数据则放在另一个磁盘分区下的 `/usr` 和 `/var` 目录中。即使系统分区损坏了，用户的数据和软件仍然安全。

随着现代硬盘容量成倍增长，以及底层启动技术（initramfs）的进步，现代 Linux 发起了 **Usr-Merge** 运动：
- 经典的底层目录 `/bin`、`/sbin`、`/lib` 全部变成了软链接，指向 `/usr/bin`、`/usr/sbin`、`/usr/lib`。
- 现在的 `usr` 目录成为了系统软件唯一的大本营，所有的核心命令和库文件都放在这里。

无论时代怎么变，以下这几个目录的职责从未改变：
- `/boot`：存放系统启动所需的核心文件，如内核映像（vmlinuz）和引导加载器配置文件（grub）。
- `/etc`：存放全局纯文本配置文件，如网络配置、用户账户信息等。
- `/root` 和 `/home`：分别是 root 用户和普通用户的主目录。
- `/var`：存放系统运行过程中会不断变化（动态增长）的数据，如日志、邮件队列和数据库文件等。

过去系统运行时的动态数据（如进程的 PID 文件）放在 `/var/run` 目录下，但 `/var` 目录的设计初衷是存放可变数据，通常在物理硬盘上。现代 Linux 将运行时数据提拔到了根目录的 `/run`，并强制将其挂载为 tmpfs（内存文件系统），实现断电即焚，**这样每次开机 `/run` 都是干干净净的**。

`/proc` 与 `/sys` 是内核动态生成的接口，供用户空间程序访问内核数据结构和系统状态。
- `/proc` 早期设计，以数字命名的文件夹代表正在运行的进程（PID），后来逐渐演变成一个内核状态的虚拟文件系统，暴露了大量内核参数。
- `/sys` Linux 2.6 内核引入的现代设计。它以结构化的设备树形式，细粒度地暴露了底层硬件和驱动信息，你甚至可以通过修改这里的文件来直接控制底层硬件（比如调节风扇转速或屏幕亮度）。

外部设备的接入也有明确的分工：
- `/mnt`：传统的挂载点，供系统管理员手动敲命令、临时挂载其他文件系统。
- `/media`：现代桌面 Linux 引入的目录，专门用于自动挂载可移动媒体设备（如 U盘、CD-ROM），主打即插即用。

其他特殊目录：
- `/dev`：“一切皆文件”的体现，你的硬盘、键盘在这里都有一个对应的“设备节点”。现代 Linux 使用 `udev` 动态管理它——插上鼠标瞬间生成文件，拔下瞬间消失。
- `/opt`：是可选的第三方软件专用目录，通常用于存放不受系统包管理器控制的软件，如商业软件、游戏等。
- `/snap`：存放 Snap 格式软件包的挂载点。Snap 是 Ubuntu 主推的沙盒化应用格式，自带所有运行依赖，与宿主系统严格隔离。


## 2. 基于 U-G-O 的多用户权限模型

每个能进入系统的用户都会被分配一个唯一的 User ID（UID），同时为了方便团队化管理，用户还会被归入一个或多个用户组（Group ID, GID）。Linux 主要通过 `/etc` 下的三个配置文件来静态跟踪管理用户与组信息：

1. `/etc/passwd`：存储用户的公开属性。格式为 `用户名:密码占位符(x):UID:GID:描述信息:主目录:默认Shell`。
2. `/etc/shadow`：存储用户的加密密码（如 SHA-512，`$6$` 开头）及安全策略，仅限 root 读写。
3. `/etc/group`：存储用户组信息。格式为 `组名:组密码占位符:GID:附属成员列表`。

在 Linux 内核中，每一个运行中的进程实际上维护着一个“身份矩阵”，用来动态标识它的权限和归属。

![身份矩阵](<images/3. shell/table-0.png>)

系统中的每个文件或目录拥有 10 个字符组成的访问控制列表，结构为 1 + 3 + 3 + 3（可通过 `ls -l` 查看）：
- 第 1 位（对象类型）：`-` 代表普通文件，`d` 代表目录，`l` 代表符号链接。
- 后 9 位（权限控制）：严格按照 User (属主)、Group (属组)、Others (其他) 的顺序，分为三组，每组三个字符。

![权限控制](<images/3. shell/table-1.png>)

创建新文件或目录时，Linux 会自动将其属主和属组绑定为当前生成该文件的进程的 EUID 和 EGID。其初始访问权限通过一个**位运算（按位与非）**逻辑动态计算得出：`基础全权限 & ~权限掩码 (umask) = 最终默认权限`。
- 基础全权限：普通文件为 `666` (`rw-rw-rw-`)；目录因需要进入，基础值为 `777` (`rwxrwxrwx`)。
- 权限掩码 (umask)：用于在创建对象时“强制剔除”不希望赋予的权限位。默认为 `0022`。
> *注：不要把 umask 误解为简单的减法！如果 umask 是 0033，创建文件的权限绝不是 666-033=633（文件不可能默认带执行权限 x），而是利用位运算强行拿掉 w 和 x，最终文件权限为 644。*

这种基于运行进程自动分配属主/属组的默认机制，在团队协作中会产生权限壁垒：用户 A 创建的文件默认归属 A 的私有组，即使用户 B 与 A 同处一个共享目录，B 也无法获得修改权限。
为了打破默认私有化继承造成的团队协作壁垒，或允许普通用户执行高权限特定操作，Linux 引入了独立于基础 rwx 之外的三个特殊权限位。

在八进制中占据最前面的第 4 个数字（例如 `4755`，`2770`）

![特权位](<images/3. shell/table-2.png>)

## 3. 核心命令：

1. 用户与组管理 (需 root 权限)
`useradd` / `usermod`：创建新用户 / 修改已有用户属性（如附加到新组）。
`groupadd` / `groupmod`：创建新用户组 / 修改已有组属性。

2. 文件权限管理
`chmod [选项] 模式 文件`：改变文件/目录的读写执行权限。
```sh
chmod 755 file  # 7 (rwx) 属主，5 (r-x) 属组，5 (r-x) 其他
chmod 2770 dir  # 2 (SGID) + 7 (rwx) 属主，7 (rwx) 属组，0 (---) 其他

chmod [ugoa][+-=][rwxXst] file  # u(user), g(group), o(others), a(all); +(添加), -(移除), =(设置)

chmod u+x dir -R  # 递归添加属主的执行权限，常用于目录以允许进入
```

`chown [选项] 属主[:属组] 文件`：改变文件的属主/属组（仅 root 可执行）。
`chgrp [选项] 属组 文件`：仅改变文件的属组。执行者必须是文件的属主且为目标新组的成员。
`umask [八进制值]`：查看或临时设置当前 Shell 会话的权限掩码。

**场景一：SUID 的权限跃迁（以 `passwd` 为例）**
> 现代 Linux 将密码哈希移至 `/etc/shadow`，权限极严（`000` 或 `640`），彻底阻断普通用户读写。为了让普通用户能修改自己的密码，`/usr/bin/passwd` 程序被赋予 SUID 权限（`4755`，属主为 root）。执行时进程的 EUID 被临时提升为 0 (root)，从而顺利写入 `/etc/shadow`。
> **⚠️安全限制**：SUID 只能作用于编译好的二进制可执行文件（如 C 语言写的程序），为了防范提权漏洞，**内核底层直接屏蔽了 SUID 在 Bash/Python 等脚本上的生效**。

**场景二：SGID 与团队共享目录**
> 将共享目录设置 SGID 位（例如 `2770`，即 `rwxrws---`），无论哪个用户在该目录下创建文件，都会自动继承该目录的属组，从而实现无缝的团队协作。

**场景三：Sticky Bit 与 `/tmp` 的安防设计**
> 根目录下的 `/tmp` 权限是 `1777`（`drwxrwxrwt`）。所有人都有 `rwx`，大家都可以往里扔临时文件。但加了粘滞位 `t` 之后，**每个人只能删除自己创建的文件，不能手贱删掉别人的临时文件**。

3. 基础操作命令

**创建、复制与移动**
`mkdir 目录`：创建新目录，`-p` 选项允许递归创建缺失的父目录。
`touch 文件`：创建空文件，或更新时间戳（`-a` 访问时间，`-m` 修改时间）。
`cp 源文件 目标`：复制，`-r` 选项递归复制目录。
`mv 源文件 目标`：移动或重命名。（在同文件系统内移动/重命名，底层仅修改目录项，文件的 inode 和时间戳保持不变。）

**删除**
`rmdir 目录`：安全的删除命令，仅能删除空目录。
`rm 文件/目录`：删除文件或目录。`-i` 交互式确认，`-r` 递归删除，`-f` 强制删除。

**链接（重点底层逻辑）**
`ln 源文件 目标`：硬链接。与源文件共享同一个 inode。
> **⚠️硬链接的两大禁忌**：1. **不能跨文件系统**（不同磁盘的 inode 编号体系是独立的，跨盘指认会导致混乱）；2. **不能链接目录**（极易在文件树中造成死循环，拖死系统遍历工具）。
`ln -s 源文件或目录 目标`：软链接（符号链接）。独立创建新文件（拥有新 inode），内容是指向源的路径字符串。支持跨文件系统和目录。

**查看文件**
`file 文件`：查看真实文件类型。
`cat 文件`：查看文本内容。`-n` 显示行号。
`more` / `less 文件`：分页显示。`less` 支持上下翻页和 `/[关键词]` 搜索。
`head` / `tail 文件`：查看文件头尾。常用 `tail -f 文件名` 实时滚动监控日志。

4. 系统管理与进程控制

> Linux 进程间通过信号（Signal）进行通信。系统管理员通过监测指令定位进程，并发送相应的信号进行控制。

**发送信号**
`kill [选项] PID`：通过进程 ID 发送信号。默认发送 15 (TERM)。
`killall [选项] 进程名`：通过进程名发送信号，作用于所有匹配的进程。

![信号](<images/3. shell/table-3.png>)

**进程监测**
`top` / `htop`：实时监测系统资源使用情况。
`ps [选项]`：现代 Ubuntu 默认支持三种风格的参数。**日常最高频使用：`ps aux`（查进程全景）和 `ps -ef`（查进程树级联关系）。**

![ps 核心参数风格](<images/3. shell/table-4.png>)

**磁盘管理**
`lsblk`：列出系统块设备树状结构。`lsblk -f` 可额外显示文件系统类型和 UUID。
`mount [选项] 设备位置 挂载点`：手动挂载。使用 UUID 挂载（如在 `/etc/fstab` 中）可以避免设备节点名称（如 `/dev/sdb1`）因硬件插拔变动而导致的挂载失败。
`umount 挂载点`：卸载设备。**注意：必须先 `cd` 退出该挂载点目录，否则会报 device is busy。**
`df -h` / `df -Th`：查看磁盘整体空间及文件系统类型。
`du -sh 目录`：查看特定目录的总实际占用空间。

## 4. 数据处理命令


![数据处理](<images/3. shell/table-5.png>)

场景：查看当前目录下占用空间最大的前 10 个文件/目录：
```sh
du -sh * | sort -hr | head -n 10
```

场景：找出系统中占用内存过高的指定进程，并**过滤掉 grep 自身的进程**：
```sh
ps aux | grep -E "java|python|ruby" | grep -v "grep" | sort -k 4 -nr | head -n 5
```

1. 压缩与归档

Linux 中必须厘清**归档（打包）**与**压缩（瘦身）**的区别。
* 压缩工具（针对单文件）：`gzip` (.gz)、`bzip2` (.bz2)、`zip` (.zip)。
* 归档工具（针对整个目录）：`tar`。

最标准的姿势是：用 `tar` 负责把整个目录打包，并同时调用 `gzip` 进行压缩。

![压缩与归档](<images/3. shell/table-6.png>)

**终极实战口诀：**
* 打包并压缩：`tar -zcvf archive.tar.gz /path/to/directory`
* 解压开源源码包：`tar -zxvf archive.tar.gz`
