## 安装软件

在 Linux 早期，安装软件是一件痛苦的事，幸好 Linux 开发人员已经通过将软件打包成更易于安装的**预编译包**（整合了程序、库和配置文件的二进制集合），这些软件包托管在远程的软件仓库中，用户只需通过包管理系统（Package Management System, PMS）即可实现一键下载、安装及自动处理依赖关系。

PMS 的不足之处在于没有统一标准的工具，不同的 Linux 发行版的 PMS 差别很大，广泛使用的有两种：

- 基于 Debian 的发行版（如 Ubuntu 和 Linux Mint）使用的是 `dpkg`
- 基于 Red Hat 的发行版（如 Fedora, openSUSE 和 Mandriva）使用的是 `rpm`

### 1. 基于 Debian 的系统

Debian 及其衍生发行版（如 Ubuntu）构建了一套从底层到高层的包管理工具链。

| 工具名称 | 工具层级 | 核心特点 |
| :--- | :--- | :--- |
| dpkg | 底层包管理系统 | 可以直接操作 `.deb` 文件，但不具备联网能力。 |
| apt-get / apt-cache | 经典前端工具 | 早期 apt-get 负责安装，apt-cache 负责查询，现代合并为 apt |
| apt | 现代前端工具 | 增加了进度条和颜色高亮功能 |
| aptitude | 高级前端工具 | 有最强大的依赖解析引擎，以及全屏交互界面 |

> aptitude 在面对复杂依赖版本冲突时，会提供多种降级或替换方案，而不是直接报错。

1. 搜索与查询

`apt search <包名>` 搜索仓库中的包
`apt show <包名>` 查看包的详细信息（包含版本、依赖列表、维护者信息）

2. 安装与更新

`sudo apt update` 拉取仓库的最新清单，同步本地索引
`sudo apt install <包名>` 安装包（自动计算并安装所需的关联库）
`sudo apt upgrade` 升级现有包，不会为了解决冲突而擅自删除包

3. 卸载与清理

`sudo apt remove <包名>` 卸载（保留配置）
`sudo apt purge <包名>` 彻底卸载（包含配置）
`sudo apt autoremove` 清理无用依赖

4. 深入文件系统

无论使用 `apt` 还是 `aptitude` 安装的软件，其记录最终都会落地到 `dpkg` 的数据库中。

`dpkg -L <包名>` 查看某软件安装了哪些文件
`dpkg --search <绝对路径>` 反查某文件属于哪个包

5. aptitude 的核心操作（应对复杂依赖）

虽然日常操作多用 `apt`，但在处理底层依赖冲突（例如多版本 C++ 库）时，`aptitude` 的自动降级与求解算法是最佳保底方案。

`aptitude` 启动全屏交互界面（使用方向键和回车浏览，按 q 退出）
`aptitude search <包名>` 搜索软件包（前缀：i 已安装, p 仓库有但未安装, c 软件已删配置还在, v 虚拟包）
`aptitude show <包名>` 查看详细信息
`sudo aptitude install <包名>` 安装软件
`sudo aptitude safe-upgrade` 安全更新系统（只更新现有包，不破坏既有依赖关系的稳定升级）
`sudo aptitude remove <包名>` 卸载软件（保留配置）
`sudo aptitude purge <包名>` 彻底清除软件及配置

### 2. 基于 Red Hat 的系统

Red Hat 及其衍生发行版（如 CentOS、Fedora）主要依赖 `rpm` 底层工具和 `yum` 前端管理工具。

| 工具名称 | 工具层级 | 核心特点 |
| :--- | :--- | :--- |
| rpm | 底层包管理系统 | 直接操作 `.rpm` 文件，不具备自动联网和解决依赖的能力 |
| yum | 前端工具 | 自动联网获取软件并解决依赖关系 |
| zypper / urpm | 前端工具 | openSUSE (zypper) 和 Mandriva (urpm) 的等效前端工具 |

1. 安装与更新

`yum install <包名>` 安装包（自动计算并安装关联依赖）
`yum localinstall <包名.rpm>` 安装本地下载的 rpm 文件，并自动利用仓库补全缺失依赖
`yum list updates` 列出当前系统所有可用的更新包
`yum update <包名>` 更新指定的软件包
`yum update` 全局升级系统中所有的软件包

2. 卸载与清理

`yum remove <包名>` 卸载软件（保留数据和配置文件）
`yum erase <包名>` 彻底删除软件及配套的所有文件

3. 仓库管理与依赖排错（损坏修复）

`yum repolist` 显示当前系统配置的软件仓库列表（仓库源文件位于 `/etc/yum.repos.d/` 目录）
`yum clean all` 清理本地缓存数据（常用于修复因文件错位导致的依赖损坏）
`yum deplist <包名>` 显示指定包底层的库依赖关系及具体的提供者（底层排错利器）
`yum update --skip-broken` 升级时忽略存在依赖损坏的包，跳过它们继续更新其他包

### 3. 从源码安装 (Tarball)

当官方仓库缺乏预编译包，或工程项目需要自定义 C/C++ 编译参数时，就需要直接通过源码压缩包（Tarball）进行编译安装。

标准构建流程：

`tar -zxvf <包名.tar.gz>` 解包源代码压缩文件
`cd <解压后的源码目录>` 进入目录（执行后续操作前，强烈建议先阅读 `README` 或 `INSTALL` 文件）
`./configure` 检查当前 Linux 系统的编译器及底层库依赖，校验通过后生成 `Makefile` 构建文件
`make` 调用底层编译器，根据 Makefile 的规则将源码编译为二进制可执行文件
`sudo make install` 将最终编译生成的二进制文件、库文件复制安装到 Linux 系统的标准路径下（如 `/usr/local/`）
